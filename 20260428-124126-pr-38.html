Executive Summary ¶

This PR vendors src/go/guestagent and src/go/networking (filter-repo'd from rancher-desktop@c8cd431, ~494 commits) into the repo and rewires the Dockerfile to build the four VM binaries from local sources instead of cloning upstream. The mechanical change — git clone … rancher-desktop removed; COPY src /rd plus per-module WORKDIR + go build blocks — is correct and removes the only network egress from Stage 1 of the image build. The cost is structural: this repo now owns the imported source, but the supporting machinery (CI test invocation, repo overview, dead Windows-host tree) does not yet reflect that ownership.

The reviews surface two categories of findings. PR-specific structural issues (I1–I3): the project's own steering text contradicts the new layout, the ~1250 lines of imported tests have no signal in this repo, and the Windows host-side cmd/host/ tree plus its winio/hvsock dependencies are vendored but never built. Inherited bugs in the imported code (I4–I12): a RemoveAll path that drops UDP protocol info, an inverted isTimeout predicate, a go vet failure that breaks go test ./... on Linux, port-keyed maps that clobber multi-IP bindings, an iptables-rule map that leaks for multi-port containers, a vm-switch retry loop that reuses a closed file descriptor, and several other concurrency/lifecycle gaps. None of these are introduced by the PR — they exist in upstream rancher-desktop at the import SHA — but they are this repo's problem the moment the import lands.

No critical, fresh-introduced regressions. Verdict is merge with fixes: ship the structural ones with the PR, file the inherited bugs as follow-up issues here (and ideally upstream).

Critical Issues ¶

None. The imported code carries real bugs (see Important Issues below), but they exist in upstream rancher-desktop@c8cd431 and ship in production today; they are not introduced by this PR.

func (p *PortProxy) acceptUDPConn(sourceConn *net.UDPConn, targetAddr *net.UDPAddr) {
	targetConn, err := net.DialUDP("udp", nil, targetAddr)
	if err != nil {
		logrus.Errorf("failed to connect to target address: %s : %s", targetAddr, err)
		return
	}
	defer targetConn.Close()
	p.wg.Add(1)
	for {
		b := make([]byte, p.config.UDPBufferSize)
		n, addr, err := sourceConn.ReadFromUDP(b)
		if err != nil && n == 0 {
			logrus.Errorf("error reading UDP packet from source: %s : %s", addr, err)
			if errors.Is(err, net.ErrClosed) {
				p.wg.Done()
				break
			}
			continue
		}
		logrus.Debugf("received %d data from %s", n, addr)

		n, err = targetConn.Write(b[:n])
		if err != nil {
			logrus.Errorf("error forwarding UDP packet to target: %s : %s", targetAddr, err)
			if errors.Is(err, net.ErrClosed) {
				p.wg.Done()
				break
			}
			continue
		}
		logrus.Debugf("sent %d data to %s", n, targetAddr)
	}
}

func (p *PortProxy) Close() error {
	// Close all the active listeners
	p.cleanupListeners()

	// Close all active UDP connections
	p.cleanupUDPConns()

	// Close the listener first to prevent new connections.
	err := p.listener.Close()
	if err != nil {
		return err
	}

	// Signal the quit channel to stop accepting new connections.
	close(p.quit)

	// Wait for all pending connections to finish.
	p.wg.Wait()

	return nil
}

cleanupListeners and cleanupUDPConns close the listening sockets but not the data connections that acceptTraffic and acceptUDPConn already accepted (each one increments wg). utils.Pipe blocks on io.Copy until both sides EOF, and acceptUDPConn blocks on ReadFromUDP until sourceConn closes — so as long as a single keepalive or streaming session is open, wg.Wait() never returns. The wsl-proxy shutdown path hangs until systemd's TimeoutStopSec force-kills it.

Fix: track the active net.Conns in a slice or map, and close them in Close() before waiting on wg. The clean shutdown is "stop accepting → close in-flight → wait for goroutines."

Design Observations ¶

Concerns ¶

Vendoring vs. upstream module dependency (in-scope) Claude. The PR description notes the source SHA and the replace directive, but does not articulate the operational benefit of vendoring over a pinned go get against tagged upstream releases. The alternative — keep go.mod pointing at a tagged rancher-desktop release, vendor a tarball into the build cache for offline use — would let dependabot keep this repo's modules current, run upstream's tests, and drop S1–S5 from this review. Jandubois's PR comment ("Even that seems excessive if we move the sources eventually to rancher-desktop-daemon") flags the same tension. Worth one paragraph in the merge commit or PR description on why we vendor here-and-now rather than waiting for the daemon repo.

Inherited bugs come with ownership (in-scope) Claude. Ten of the fifteen Important findings (I4–I15) are pre-existing upstream bugs surfaced by the import. Before this PR they belonged to rancher-desktop; after, they belong here too. The team needs an explicit triage policy: file each as a follow-up issue against this repo, sync with upstream so fixes go in once, and set a cadence for re-importing the upstream sources or backporting fixes here.

No reconciliation between guestagent and wsl-proxy (future) Gemini. The APITracker fires events at wsl-proxy and forgets them. A wsl-proxy restart wipes its mapping table and there is no resync — the closest thing to a recovery path is a container restart that re-emits the event. A pull-based contract (wsl-proxy queries guestagent on startup) or a periodic full-state push would survive proxy restarts. I14 is the visible symptom; the structural fix is broader.

Strengths ¶

  • Network-free Stage 1 build Claude Codex. Replacing git clone https://github.com/rancher-sandbox/rancher-desktop with COPY src /rd removes the only network egress from gobuild. The image is now reproducible offline; CI runners no longer race github.com rate limits or DNS.
  • Per-module build isolation Claude. Each WORKDIR + go build block is short, isolated, and uses BuildKit cache mounts. Build flags (-ldflags '-s -w') match the deleted block; no binary-size regression.
  • replace keeps the modules buildable in place Codex. The replace github.com/rancher-sandbox/rancher-desktop/src/go/guestagent => ../guestagent line lets networking resolve guestagent from the local copy without a second checkout. This is the right minimum pattern for two co-vendored modules.
  • Earlier review feedback addressed Claude. The src/go/guestagent/guestagent binary that prior inline comments flagged is no longer in the tree.

Testing Assessment ¶

The repo has no automated test invocation today (overview: "No test suite in the repo. Verification is by booting the produced images.") and this PR keeps that posture, even though it imports ~1250 lines of upstream tests. Specific gaps surfaced by the review:

  1. (highest risk) apitracker.go Add/Remove/RemoveAll semantics — apitracker_test.go covers these upstream and ships in this PR, but never runs. I5 would be caught by an end-to-end UDP unexpose test, but no such test exists.
  2. iptables.go comparePorts and ForwardPorts partial-failure handling — iptables_test.go exists but does not exercise the failure-after-state-update path that breaks I9.
  3. portproxy/server.go add+remove flow — server_test.go covers single-binding-per-port. It does not exercise multi-host-IP bindings (I7), Close() while connections are active (I15), or two-way UDP (I11).
  4. Linux build sanity broken by I6. GOOS=linux go test ./... in src/go/guestagent fails under vet at servicewatcher_linux.go:93. Codex verified that go test ./... on darwin (which excludes the Linux-only files) still passes; GOOS=linux go build ./... and GOOS=windows go build ./... both pass for networking. The failure mode is in go test's vet pass, not the compiler.
  5. No smoke test confirms the produced binaries exec at boot. make distro.raw.xz exercises the build paths; no test asserts that rancher-desktop-guest-agent and vm-switch come up under systemd in a booted image.

I2 plus a fix for I6 would unblock #1–#4. #5 is a pre-existing gap.
