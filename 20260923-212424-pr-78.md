## Executive Summary

This PR deletes the Rancher Desktop guest files from `root/` and the `config.sh` steps that placed, enabled and chmodded them. RD2 PR #837 supplies them through the distro-overlay manifest. Applying #837's overlay to this PR's CI images reproduces the merge-base images on both profiles, apart from the deletions RD2 #805 planned and a `/root` mode change. The one risk is merge order. If this PR merges first, overlaying this repo's images from RD2 `main` yields guests without Rancher Desktop units.

## Review Process Notes

### Skill improvements

- Before the prompt states that a CI job exercised the artifact under review, confirm from the job log what the tested system actually loaded, not only what the job downloaded. A job can download the artifact and then build or boot something else, and every agent builds on a fact the prompt calls established.
- When the prompt lists facts the orchestrator has established and tells agents not to repeat the work, also ask them to report any evidence that contradicts one. An agent that finds a contradiction should raise it as a finding.
- The check-results step should cover `workflow_run`-triggered workflows. Their runs do not appear in the head commit's check list, and they execute the default branch's copy of the workflow, so compare that copy with the branch's before judging the PR's CI.

### Citation lint

S3 cites commit `76696d594`, because the file whose deletion caused the mode change no longer exists at the review SHA. The citation lint flags it as unresolved; the citation is deliberate.

### Repo context updates

- UPDATE the BATS entry: `.github/workflows/bats.yaml` runs on `workflow_run` after Build, so it executes the default branch's copy of the workflow and its result does not appear among a PR's checks. Find a PR's run with `gh run list --workflow bats.yaml` and match the run id in its "Download image" step. It builds rancher-desktop-2 `main` with the image under test staged through `STAGE_DISTRO`, so a PR that removes guest files whose overlay entries are still in an unmerged rancher-desktop-2 PR fails there until that PR merges.
- ADD: Rancher Desktop guest files, their modes and their `systemctl enable` links come from rancher-desktop-2's `rdd/overlay/manifest.yaml`, not from `root/` or `config.sh`. A change that removes a file or step here is correct only if the manifest supplies the same path, mode, profile and `.wants` link. `distro-overlay` is pure Go and runs without a VM, so verify by running it on the CI-built image for each profile and diffing the result against the image built before the change. Flag the merge order when the manifest change is not yet on rancher-desktop-2 `main`.

### Design Observations

#### Concerns

1. **Overlay manifest coverage test does not validate `.wants` symlinks or file modes** `(future)`:
   In RD2 PR #837, `pkg/overlay/manifest_coverage_test.go:24-48` parses `opensuse-guest-paths.txt` and only checks that `m.Entries[i].Path` exists in `manifest.yaml`. It does not check that the 7 `.wants` symlinks moved out of `config.sh` exist, nor does it verify that files in `overlay/root` exist on disk or carry expected execution permissions (e.g. `0755` for `wsl-exec`, `setup-namespace.sh`, and `rancher-desktop.script`). An entry could be corrupted or point to a missing source without failing `TestManifestCoversMovedGuestPaths`. Adding `.wants` symlink paths and mode assertions to the test would prevent regressions in RD2.

#### Strengths

1. **Clean separation of lifecycle concerns**:
   Retaining `/etc/dracut.conf.d/repart.conf` (consumed during initrd generation and removed by `pre_disk_sync.sh:18`) and `/usr/local/lib/repart.d/50-root.conf` (the runtime companion to `config.kiwi` partition sizing) keeps build-specific kiwi assets in this repository while cleanly moving application-specific units to the overlay.
2. **Elimination of build-time filename translation**:
   Moving `mnt-lima-cidata.mount` into RD2's manifest maps source `root/usr/local/lib/systemd/system/mnt-lima-cidata.mount` directly to destination `'/usr/local/lib/systemd/system/mnt-lima\x2dcidata.mount'`, cleanly removing the fragile `mv /usr/local/lib/systemd/system/mnt-lima{-,\\x2d}cidata.mount` workaround in `config.sh:47`.
3. **Restoration of root home directory permissions**:
   Removing `root/root/.docker/config.json` (resolving RD2 issue #446) eliminates `root/root/` from Kiwi's filesystem overlay tree, correctly allowing `/root` to retain its standard package mode `0700` (`drwx------`) rather than being overridden to `0755` (`drwxr-xr-x`).
