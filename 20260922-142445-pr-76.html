Concerns ¶

  • The workflow cannot run before it merges, and the planned ref has no input (future). workflow_run always runs the default branch's file. The BATS runs this PR's builds triggered report headSha: 369edffb9, the merge-base. Adding workflow_dispatch with build-run-id and rd2-ref inputs would let a branch run its own copy and give the TODO's ref a source. Claude Opus 5.5
  • The qcow2 artifact is built and released, but no job boots it (future). RD2 embeds raw on every non-Windows target, and this PR moves the Linux leg to raw. The old qcow2 leg never reached the suite either (#804), so nothing is lost. Decide whether qcow2 still has a consumer; if not, drop it from build.yaml, release.yaml and README.md:9. Claude Opus 5.5 Gemini 3.5 Flash

Testing Assessment ¶

This is CI-only code, and it first runs after merge, because workflow_run executes the default branch's file. Most wiring failures will be loud, because a bad download, readlink or make error fails the job. The silent case is a fall-back to the release image, which S1 would catch.

A live main run (35754729073, macOS leg) confirms the mechanism #804 describes. After rewriting the manifest, download-guest-deps downloaded distro.v0.2.8.amd64.raw.xz and copied it to overlay/build/distro.raw.xz, so the VM would have booted the release image.

Two Windows steps are reasoned, not executed. The first is MSYS2 bash appending to the Windows-form $GITHUB_ENV; no existing run-in-shell step in this workflow or RD2's writes $GITHUB_ENV. The second is cygpath -m output reaching go run … --stage 'distro=D:/…'. The first post-merge Windows run settles both. No agent and no local run can exercise the workflow; I ran no test suite, since the change touches only the workflow.

Documentation Assessment ¶

README.md:9 still calls qcow2.xz the image "For Linux/qemu hosts", while RD2 boots raw on Linux; see the qcow2 concern above. The PR body's Fixes: is I1.

Review Process Notes ¶

Skill improvements ¶

  • When a PR body uses a closing keyword (Fixes, Closes, Resolves) on an issue with several requests, check each request against the diff, and flag a closing reference to an issue the PR only partly addresses, because the merge closes it and the deferred part leaves the open list.
  • When a workflow triggers on workflow_run (or pull_request_target), the PR's CI ran the default branch's copy of that file, so state that the change is unexecuted and read any "passing" run's headSha before citing it as evidence.

Repo context updates ¶

When reviewing it, diff its runner-setup steps against the RD2 workflow of the same date and flag steps RD2 added that affect the guest (kernel parameters, VM sizing); rate them as pre-existing gaps unless the PR removed them.
