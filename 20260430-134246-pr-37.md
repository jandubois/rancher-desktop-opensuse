## Important Issues

I1. **Tight loop on `Accept` errors** — `src/rdd-guest/main.go:43-50` [Gemini 3.1 Pro]

```go
conn, err := l.Accept()
if err != nil {
    if ctx.Err() != nil {
        return
    }
    log.Printf("rdd-guest: accept: %v", err)
    continue
}
```

When `l.Accept()` returns a persistent non-shutdown error — `EMFILE` on file-descriptor exhaustion, `ENFILE` on system-wide exhaustion, `ENOMEM` under memory pressure — the loop logs and immediately retries with no backoff. The condition does not self-clear instantly: the kernel still refuses to allocate, so `Accept` returns the same error microseconds later. The result is a hot CPU loop that pegs a core and floods `journalctl` with thousands of identical lines per second until something else frees the fd or the process is restarted by an operator.

`Restart=on-failure` does not help because the process never exits. The bridge runs as root, and `LimitNOFILE` for systemd services defaults relatively low, so this is a realistic production failure mode for any vsock service that holds a long-lived connection per Docker API call.

Fix: backoff briefly on accept errors so the process yields the CPU and the journal stays readable.

```diff
 		conn, err := l.Accept()
 		if err != nil {
 			if ctx.Err() != nil {
 				return
 			}
 			log.Printf("rdd-guest: accept: %v", err)
+			time.Sleep(100 * time.Millisecond)
 			continue
 		}
```

S1. **In-flight connections aborted on shutdown — round 1 S5 unaddressed** — `src/rdd-guest/main.go:42-53` [Claude Opus 4.7]

```go
for {
    conn, err := l.Accept()
    if err != nil {
        if ctx.Err() != nil {
            return
        }
        ...
    }
    go handleConn(ctx, conn)
}
```

The author added a `sync.WaitGroup` inside `pipe()` (`main.go:99-114`), which serializes the two `forward` goroutines — but the `handleConn` goroutines launched at line 51 are still untracked at the program level. When `SIGTERM` arrives, `<-ctx.Done()` closes the listener, `Accept` errors, the loop returns, and `main` exits with active connections mid-`io.Copy`. The OS reaps their fds, peers see an abortive close instead of the bidirectional half-close drain `pipe` was carefully written to deliver. Long-running Docker calls (`exec`, `attach`, `events`, `logs -f`, image pulls) get truncated mid-stream.

The internal WaitGroup is the right primitive — it just needs to live one scope up.

```diff
 func main() {
     ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
     defer stop()
     ...
+    var wg sync.WaitGroup
     for {
         conn, err := l.Accept()
         if err != nil {
             if ctx.Err() != nil {
+                wg.Wait()
                 return
             }
             log.Printf("rdd-guest: accept: %v", err)
             continue
         }
-        go handleConn(ctx, conn)
+        wg.Add(1)
+        go func() {
+            defer wg.Done()
+            handleConn(ctx, conn)
+        }()
     }
 }
```

A short systemd `TimeoutStopSec=` in the unit caps the drain so a stuck connection cannot wedge `systemctl restart`.

S4. **Dead `io.EOF` check in proxy loop** — `src/rdd-guest/main.go:104-107` [Gemini 3.1 Pro]

```go
_, err := io.Copy(dst, src)
if err != nil && !errors.Is(err, io.EOF) {
    log.Printf("rdd-guest: copy: %v", err)
}
```

`io.Copy`'s contract guarantees that EOF on `src` is not surfaced as an error: "A successful Copy returns err == nil, not err == EOF, because Copy is defined to read from src until EOF, it does not treat an EOF from Read as an error to be reported." So `errors.Is(err, io.EOF)` is unreachable under the documented contract; any non-nil `err` here represents a genuine fault (`ECONNRESET`, `EPIPE`, write error to a closed `dst`) worth logging. The check also drags in `errors` purely for this unreachable branch.

```diff
 		_, err := io.Copy(dst, src)
-		if err != nil && !errors.Is(err, io.EOF) {
+		if err != nil {
 			log.Printf("rdd-guest: copy: %v", err)
 		}
```

After the change, the `errors` import becomes unused — drop it from the import block.

`(suggestion, enhancement)`

## Review Process Notes

### Skill improvements

- **Add a review dimension on tight retry loops.** When a PR introduces a `for { … }` loop that calls a syscall-backed accept/read/recv with `continue` on error, the prompt should ask: does the error class self-clear instantly, and if not, will this hot-loop the CPU? `EMFILE`, `ENFILE`, `ENOMEM`, and persistent `EAGAIN` on a non-blocking listener are the textbook cases. Naming the pattern in `dimensions.md` raises the chance future agents flag it without having to reason from first principles each time.
  *Why:* Two of three agents missed this on PR #37 round 2 even though the loop is six lines and the failure mode (CPU peg + journal flood) is well-known. A named dimension turns a "you have to know to look for it" issue into a "the prompt asks about it" issue.

### Repo context updates

- **Document the engine-conditional unit pattern.** When a systemd unit serves a backend that is engine-gated (`docker`/`moby` vs `containerd`), the convention in this repo is `EnvironmentFile=-/etc/sysconfig/rancher-desktop` plus `ExecCondition=test ${CONTAINER_ENGINE} = <engine>`. Examples live at `docker.service.d/conditional.conf:3`, `containerd.service.d/conditional.conf:3`, and `buildkitd.service:10-11`. Reviewers of new WSL-side units should check whether the new unit serves an engine-specific resource and apply the same pattern; running an engine-specific bridge under the wrong engine produces journal noise and wasted listeners.
  *Why:* This pattern is consistent enough across the repo to count as project convention, but it is invisible from a single-file diff. Codifying it lets future reviews flag the gap at Suggestion without re-deriving the pattern from scratch.

# Deep Code Review — PR #37: Add rdd-guest socket bridge

## Executive Summary

Adds `rdd-guest`, a small Go program built into the WSL2 image that bridges vsock port 6660 to `/var/run/docker.sock`, plus the systemd unit and Dockerfile/config.sh wiring to install and enable it. The implementation is small and self-contained; main concerns are non-graceful shutdown of in-flight connections and a few unresolved review nits (godoc convention, build artifact in `.gitignore`).

## Findings

### Critical Issues

None.

### Important Issues

**I1. In-flight connections aborted on shutdown** — `src/rdd-guest/main.go:42-53`

```go
for {
    conn, err := l.Accept()
    if err != nil {
        if ctx.Err() != nil {
            return
        }
        log.Printf("rdd-guest: accept: %v", err)
        continue
    }
    go handleConn(ctx, conn)
}
```

When systemd sends `SIGTERM`, the listener is closed, `Accept()` errors out, and `main()` returns at line 46. Any goroutines started at line 51 are killed mid-`io.Copy` — the OS closes their fds, the peer sees an abortive close rather than the bidirectional half-close drain the `pipe` function (lines 102-109) was carefully written to deliver. For long-running Docker API calls (`exec`, `attach`, `events`, `logs -f`, image pulls), a client mid-stream sees a truncated response. `Restart=on-failure` won't rescue this since the exit is clean.

The fix is small: track active handlers in a top-level `sync.WaitGroup` and wait before returning. (severity scaling: vsock.Listen returns an error path via `log.Fatalf` at line 32 that already short-circuits `defer stop()`, so introducing a graceful-shutdown WaitGroup is the only place left where draining happens.)

Fix:

```diff
 func main() {
     ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
     defer stop()

     l, err := vsock.Listen(vsockPort, nil)
     if err != nil {
         log.Fatalf("vsock listen: %v", err)
     }

     log.Printf("rdd-guest: listening on vsock port %d", vsockPort)

     go func() {
         <-ctx.Done()
         l.Close()
     }()

+    var wg sync.WaitGroup
     for {
         conn, err := l.Accept()
         if err != nil {
             if ctx.Err() != nil {
+                wg.Wait()
                 return
             }
             log.Printf("rdd-guest: accept: %v", err)
             continue
         }
-        go handleConn(ctx, conn)
+        wg.Add(1)
+        go func() {
+            defer wg.Done()
+            handleConn(ctx, conn)
+        }()
     }
 }
```

If the upstream `pkg/socketbridge` already implements graceful drain, the TODO at lines 55-57 will eventually replace this — but until that lands, this is the live code and should drain its own connections. (important, gap)

### Suggestions

**S1. Package doc should use `Command rdd-guest is …`** — `src/rdd-guest/main.go:1-5`

I2. **Tight loop on socket accept errors** — `src/rdd-guest/main.go:43-50`

```go
		conn, err := l.Accept()
		if err != nil {
			if ctx.Err() != nil {
				return
			}

		}
```

If `l.Accept()` fails with a temporary but persistent OS error (e.g., `EMFILE` when the process exhausts its file descriptors), the code at line 49 immediately loops without blocking. Fix: Introduce a small backoff sleep on accept errors to prevent CPU and log exhaustion.

```diff
 			if ctx.Err() != nil {
 				return
 			}
 			log.Printf("rdd-guest: accept: %v", err)
+			time.Sleep(100 * time.Millisecond)
 			continue
 		}
```

S1. **Unnecessary `io.EOF` check in proxy loop** — `src/rdd-guest/main.go:106`


The `&& !errors.Is(err, io.EOF)` check on line 106 is dead code.  		_, err := io.Copy(dst, src)
```diff
-		if err != nil && !errors.Is(err, io.EOF) {
+		if err != nil {
 			log.Printf("rdd-guest: copy: %v", err)
```
